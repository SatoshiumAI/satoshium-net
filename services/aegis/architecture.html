🛡️ Architecture Overview

Aegis: The Agent Firewall

Aegis is Satoshium’s certification-authority-grade agent firewall. It is designed as a layered, deterministic, read-only evaluation and export system that classifies authority posture, routing readiness, issuance eligibility, bundle readiness, Chronicle compatibility, and future Anchor participation without prematurely granting execution authority.

System Purpose

Aegis exists to evaluate whether a certification authority surface is stable, exportable, and trustworthy enough to participate in Satoshium’s broader trust-layer ecosystem. Rather than executing decisions directly, Aegis produces structured readiness, compatibility, and artifact surfaces that other future subsystems can inspect and verify.

Read-only by default Aegis surfaces describe state, readiness, compatibility, and exportability without granting execution rights.
Deterministic classification Routing, issuance, bundle, and compatibility outputs are derived from explicit conditions rather than hidden heuristics.
Trust-layer alignment Outputs are structured to interoperate with Registry, Chronicle, and future Anchor commitment pipelines.

High-Level Architecture

Authority projection → lifecycle posture → registry eligibility → certification routing → certification issuance → snapshot export readiness → Chronicle handshake → Anchor eligibility → Explorer bundle descriptor → artifact readiness → export intent → deterministic hash identity → Anchor commitment preview

The architecture is intentionally layered. Each surface builds on prior surfaces, preserving auditability and preventing early execution authority from leaking into discovery, export, or compatibility layers.

Trust Boundaries

  • Projection surfaces are declarative. They describe state and readiness but do not grant authority.
  • Handshake surfaces are compatibility declarations. They announce readiness for future Chronicle or Anchor interaction without triggering external actions.
  • Export surfaces are artifact-focused. They define how Aegis may be packaged, inspected, downloaded, and hashed without mutating internal evaluation logic.
  • Commitment preview is non-operative. Aegis can derive a future Anchor commitment payload shape without performing Bitcoin or Anchor operations.

Bundle & Export Model

Aegis now supports a complete export lifecycle for its certification-authority subsystem bundle:

write → inspect → manifest read → download → deterministic hash → Anchor commitment preview

The canonical bundle is represented as:

aegis-certification-authority.bundle.zip

This bundle is designed to be portable, inspectable, and hash-addressable while preserving strict separation between artifact publication and future Chronicle/Anchor execution layers.

Current Public-Facing Surfaces

  • Readiness endpoint — machine-readable operational summary
  • Bundle inspection endpoint — confirms written archive structure and manifest readability
  • Manifest access endpoint — returns manifest.json directly from the written bundle
  • Bundle download endpoint — streams the written certification-authority bundle
  • ZIP-bytes stub endpoint — returns a deterministic in-memory portable bundle representation
  • Hash surface endpoint — exposes deterministic bundle identity and content fingerprints
  • Anchor commitment preview endpoint — provides a future commitment payload shape without external writes
